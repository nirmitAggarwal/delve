# Delve theme format

Delve styles itself from semantic tokens, not from a desktop shell stylesheet.
A theme is a directory under:

```
~/.config/delve/themes/<name>/
├── theme.json    # required
└── style.css     # optional extra rules
```

It is referenced in settings as `"theme": "custom:<name>"`. Built-in themes are
`builtin:dark`, `builtin:light`, and `builtin:ember`.

## theme.json

```json
{
  "name": "My Theme",
  "dark": true,
  "colors": {
    "window_bg": "#101216",
    "accent": "#4c8dff"
  },
  "metrics": {
    "radius_small": "6px",
    "row_height": "30px"
  },
  "typography": {
    "ui_font": "",
    "mono_font": "monospace",
    "base_size": "10.5pt"
  }
}
```

All fields are optional except that a usable theme needs a valid `colors` set.
Missing colors are filled from Delve's dark or light palette according to the
`dark` flag, and missing metrics and typography values fall back to defaults, so
a small partial theme is valid.

### `colors`

Values are GTK colors: `#rrggbb`, `#rrggbbaa`, `rgb(...)`, `rgba(...)`, or a
named color. The following names are the semantic tokens used by the component
stylesheet:

| Token | Purpose |
| --- | --- |
| `window_bg` | Main window background |
| `sidebar_bg` | Sidebar background |
| `canvas_bg` | File view background |
| `toolbar_bg` | Toolbar and status bar |
| `tab_bg` | Tab strip background |
| `tab_active_bg` | Active tab background |
| `inspector_bg` | Inspector background |
| `floating_bg` | Popovers and floating surfaces |
| `overlay_bg` | Overlay surfaces |
| `text_primary` | Primary text |
| `text_secondary` | Secondary text |
| `text_muted` | Muted labels and hints |
| `text_disabled` | Disabled text |
| `text_inverse` | Text on accent surfaces |
| `accent` | Accent colour |
| `accent_hover` | Accent hover state |
| `accent_muted` | Low-emphasis accent fill |
| `focus_ring` | Keyboard focus outline |
| `success`, `warning`, `danger`, `info` | Status colours |
| `border_subtle`, `border_strong` | Borders and dividers |
| `border_selected` | Selected item border |
| `separator` | Separator lines |
| `sel_bg`, `sel_border`, `sel_multi` | Selection states |
| `hover_bg` | Row hover fill |
| `folder` | Folder icon tint |
| `shadow` | Shadows |

### `metrics`

Length values substituted into the component sheet. GTK CSS has no custom
properties for lengths, so Delve inserts these values textually.

| Metric | Default |
| --- | --- |
| `radius_small` | `6px` |
| `radius_medium` | `9px` |
| `radius_large` | `14px` |
| `border_width` | `1px` |
| `row_height` | `30px` |
| `tab_height` | `40px` |
| `toolbar_height` | `46px` |
| `status_height` | `26px` |
| `panel_gap` | `8px` |

### `typography`

| Key | Default | Notes |
| --- | --- | --- |
| `ui_font` | empty | Empty means inherit the system font |
| `mono_font` | `monospace` | Used for paths and text previews |
| `base_size` | `10.5pt` | Base window font size |
| `small_size` | `9pt` | Small labels |
| `title_size` | `12pt` | Headings |

Settings for UI font, mono font, accent, and background opacity are applied on
top of the theme and override the corresponding tokens. Opacity applies alpha
to window and panel background surfaces only; text, icons, hover and selection
colours are not faded.

## style.css

Any additional GTK CSS is appended after Delve's component sheet. Use it to
adjust a specific widget without restyling everything:

```css
.delve-tabbar {
  border-bottom-width: 2px;
}

.cell-name {
  letter-spacing: 0.2px;
}
```

Avoid hard-coded colours that duplicate the token system where possible; using
`@accent`, `@text_primary`, and the other tokens keeps your theme coherent in
both light and dark variants. Tag and folder-colour rules are generated by Delve
and must not be redefined.

## Validation and live reload

Before a theme is applied, Delve parses the complete stylesheet in a throwaway
`CssProvider`. If GTK reports an error, the current theme stays active and the
error is shown in settings. This means you can edit a theme in place without
losing the running UI.

With **Live reload** enabled, Delve watches the theme directory. Saving
`theme.json` or `style.css` re-applies the theme immediately. A theme that fails
to parse is rejected and the last good theme remains.

## Creating a theme from a built-in

In **Settings → Appearance**, use **Duplicate built-in theme** to write a
documented copy under `~/.config/delve/themes/`. Edit it and select it from the
theme picker; the built-in copy is never modified.
